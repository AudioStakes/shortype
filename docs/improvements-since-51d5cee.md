## 改善の内訳

### 1. 開発基盤が整った

`c698bce` から `73988d4` にかけて、コード品質チェックと実行環境が整理されました。

- Biome 導入で lint / format の方針がまとまった
- `npm` と `tsx` への移行で、スクリプトの入口が分かりやすくなった
- `node 24` 前提が明示され、環境差異が見えやすくなった

これは地味ですが、長期運用ではかなり効きます。ルールが揃うと、変更の判断が速くなり、レビューもしやすくなります。

### 2. 依存関係と実行環境が軽くなった

`621c376` や `c576400` 以降では、不要な依存や古い構成が減っています。

- 画像や CSV まわりの依存を整理
- Vue ベースの UI から Preact ベースに移行
- 移行後の互換修正で、開発サーバーの不安定さを解消

結果として、アプリ本体だけでなく、開発時の立ち上がりや再ビルドのストレスも減りました。

### 3. 画面の使い勝手が上がった

`4d9202d`、`5d9da98`、`9e59926` は、訓練アプリとしての体験改善が中心です。

- キーラベルの見え方が整い、視認性が上がった
- ショートカット画面の操作が分かりやすくなった
- コンパクト表示で、狭い画面でも情報が詰まりすぎないようになった

ここはユーザーにとっての価値が最も見えやすい部分です。見た目の調整に見えて、実際には「次に何をすればよいか」が伝わりやすくなっています。

### 4. テストが強くなった

`083ac88` や `5d9da98` では、テストの書き方やカバー範囲が改善されています。

- テストヘルパーの整理で、前提条件が読みやすくなった
- コンポーネント単位の退行テストが追加され、画面変更に強くなった

これは UI の細かな修正を続けるほど重要になります。見た目や挙動を調整しても、壊れた部分を検知しやすくなるからです。

### 5. UnoCSS への移行で、スタイル配信の無駄が減った

`adc2e00` では、Tailwind の一括読み込みから UnoCSS のオンデマンド生成に切り替えました。

- `src/main.tsx` から `virtual:uno.css` を読み込み、必要なユーティリティだけを生成するようにした
- `vite.config.ts` の Tailwind 専用プラグインを外し、UnoCSS の Vite プラグインに置き換えた
- `src/index.css` は独自ユーティリティやアニメーション定義だけを残し、役割がはっきりした

実際の production build でも、CSS bundle は `23.43 kB` から `17.80 kB` に下がり、gzip も `5.41 kB` から `3.62 kB` まで小さくなりました。

この変更のメリットは、単に依存を置き換えたことではありません。

- 使っていない CSS を配らずに済む
- Tailwind 固有の設定やプラグインに引きずられにくい
- 既存の class ベースのコンポーネント構造を大きく崩さずに、軽いスタイル基盤へ寄せられる
