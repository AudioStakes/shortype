各修正はコミット単位で独立レビューと修正を行います。残る改善を1つのPRにまとめ、既存ツールによる全検証を経て反映します。
独自の検証スクリプトや検証ツール自体のテストは追加しません。
ユーザーの指示により自動CIとCI成功の必須条件は停止しています。ローカル検証とCodexの独立レビューを継続し、実行できない検証は明記します。

残る改善は入力、保存、CSVと出題データに分担して並行実装しました。
CSV入力と生成物の検査を整えてから出題内容を更新するため、15・16を14の前に実施しました。
残項目の実装と独立レビューが完了し、クリーンな`npm ci`の後に全ローカル検証が成功しました。
最新の全検証ではauditの通信タイムアウトだけが発生し、同じ検査基準で再実行して脆弱性0件を確認しました。
単体353件を通常順・seed 1・42で実行し、本番ビルドのブラウザー15件、全設定の静的検査、全ファイルの網羅率閾値を通過しました。
全体の網羅率はlines 99.83%、statements 99.84%、functions 99.73%、branches 98.52%、mutation scoreは92.86%、npm auditの脆弱性は0件です。

項目2の修正では、Node 24のES Modulesで生成コマンドを実行できるよう、出力先の解決に標準の`import.meta.dirname`も使用しました。
問題ID、回答の保存形式、その他の生成済みレコードは維持しています。
矢印の意味は[AppleのTerminalショートカット一覧](https://support.apple.com/guide/terminal/keyboard-shortcuts-trmlshtcts/mac)で確認しました。

項目3は、回答追加・問題除外・除外解除の差分を最新の保存値へ適用し、Web Locksで同時更新を直列化します。
storageイベントでは最新値を読み直し、画面の学習状況も同期します。保存形式・キー名・問題IDは維持します。
Web Locksを利用できない環境では同時書き込みの保証はなく、保存失敗後はそのページのメモリで継続します。
未保存の進捗はページを閉じると失われるため、自動再試行は行いません。旧版のタブが残る場合はすべて再読み込みしてください。

項目4は、問題を再設定するたびに入力の世代を更新し、以前の回答や再試行の遅延処理を無効にします。
同じ問題IDの再出題、除外解除、外部タブからの復帰も対象とし、復元をキャンセルした場合は現在の回答処理を維持します。

項目5・6は、一致した別解について全画面とKeyboard Lockの取得結果を判定します。
取得中や失敗時は自己採点を使え、正解表示後に取得が成功してもY/Nの回答を継続できます。
ネイティブAPIの失敗・画面離脱・旧画面の遅延完了をテストし、古い画面が新しい画面のロックを解除しないようにしました。

項目9の未選択枠は、axe-coreのコントラスト計算で通常時4.759:1、ホバー時4.324:1を確認しました。
項目14は、AppleとGoogleの公式資料を照合して既存339問のIDを維持し、342〜352の11問を追加しました。
OS・キーボードの条件を残し、追加したFnを含む6問（346〜351）は自己採点にします。旧macOSカテゴリーは、現在の選択肢で絞り込む前に移行します。

項目17は、保存値の読み込み・書き込みとページ内の回答追加を直近2回答へ限定し、出題の重みと学習状態の不変条件も確認しました。
項目18は、非互換スキーマの対象キーだけを消してから新しい値とスキーマを保存します。失敗後の再読み込みで古い設定を復活させず、無関係なキーを維持します。
設定と進捗の保存を同じWeb Lockで直列化し、待機中の設定も画面の再作成時に維持します。

項目19は、現在のChromiumでlayoutchangeが公開されていないことを確認し、フォーカスとページ表示の復帰時に配列を取得します。
取得失敗時は直前の配列を保ち、古いリクエストや破棄済み画面の結果は適用しません。
ページにフォーカスを残したままのOS・IME切り替えは自動検証の対象外です。別の画面へ移って戻ると再取得を要求します。

自動検証では、物理キーボード、OS予約キー、IME、VoiceOverの実機での動作までは保証しません。
